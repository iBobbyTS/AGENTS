# Sectioned Feature Development

## Dispatch profile and execution

The dispatch profile embedded in [model-routing.md](references/model-routing.md) is the only execution route on this host; machine-readable installation facts live in `installation.json`. Requested/observed model and actual transport are separate facts.

The profile owns concrete models and transport; this workflow owns admission and delivery. A role the host cannot invoke is a capability blocker: report it and the installation action; do not imitate the role locally or invent a bridge. A user instruction naming another host's executor is the same blocker — product scope that names a host (for example “修复 external-subagent 的 zcode adapter”) is product scope and does not change execution.

## One canonical plan; actual delegated execution

1. Inspect authority, dirty work, branch/base and loaded skill version. Read [efficiency checkpoints](references/efficiency-checkpoints.md) once at activation/takeover; the baseline checkpoint fires before S01.
2. Main writes `.agent-work/PLAN-FULL.md` using the [template](assets/PLAN-FULL.template.md): business outcomes, existing owners, exclusions, dependencies, checks, concrete boundary examples and explicit `impl_std`/`impl_large` assignments. Read [planning/router.md](references/planning/router.md) once; use matching knowledge, not the whole planning index on every pass. A section whose changes share mutable async state must declare shared invariants and an interleave oracle (entry × state family × outcome) in the PLAN; per-item functional ACs alone do not bound its review. Validate basic structure once and after structural changes with `section_plan.py validate`; its output never grants permission.
3. Freeze the plan. Obtain two independent clean coverages through the embedded profile under [reviewer orchestration](references/reviewer-orchestration.md). Main admits only proven material candidates. Resolve owner decisions and affected delta closure before S01. A NIT is not a failed review.
4. Generate the dispatch view `sections/{id}-TASK.md` with `section_plan.py extract --output`, adding only the [template](assets/TASK-PACKET.template.md) header fields — never hand-writing the section body. Actually dispatch the selected implementer and wait for its terminal result. Authorize exactly one report path under `.agent-work/` per dispatch: the worker writes its [HANDOFF](assets/SECTION-HANDOFF.template.md) or review report there itself, and its final answer carries only the report path, the verdict signal (where the role has one) and a one-line status. A dispatch message uses the [dispatch prompt template](assets/DISPATCH-PROMPT.template.md) and carries only task facts: that TASK path, the repository location, the dispatched report path and — for a reviewer — the exact diff range or plan reference. Nothing already bound by the role's developer instruction (role law, report conventions, git prohibitions) and nothing main-owned (routing labels, execution mode, slot letters, branch/HEAD pins) ever enters a dispatch message. Before the first dispatch of a feature, main reads the bundled [role instructions](assets/ROLE-INSTRUCTIONS.md) — every role's developer instruction in one file, kept identical to the installed agent definitions and spawn profiles — and keeps prompt conventions consistent with them; reread it after any role definition changes or a result contradicts its conventions. Assume workspace continuity within a dispatch: verify git state at activation, at integration/commit and after an actual anomaly, not before each dispatch. Main schedules; it never silently replaces a required worker with its own product/test edits. [Task–model routing](references/model-routing.md) governs routing and upgrades.
5. Freeze the implemented parent candidate; follow [bounded review](references/bounded-review.md). Keep two independent clean coverages with carry-forward and silent-slot retirement exactly as [reviewer orchestration](references/reviewer-orchestration.md) defines them; never mutate a live review's candidate or accept the worker's own review.
6. Accept only after both coverages, findings and required checks close; serial successors also await prerequisite integration. Verify returned child work before consumption, using primary checkpoints at consequential handoffs—not two final reviews per child/message. Parallel work needs explicit independence, isolated worktrees and nonconflicting resources. Report actual overlap; separate filenames do not establish independence.
7. Integrate accepted work on the authorized feature branch, check the final product/test head and any unproven composition, then close and archive the completed task to `.agent-work/archive/{YYYYMMDD-HHMM_feature-id}/`: PLAN-FULL plus real evidence (requirements, final state, review reports, handoffs); delete the rebuildable dispatch views — the generated `TASK-*.md` views and any legacy PLAN extract — after an inventory. Report the [efficiency checkpoints](references/efficiency-checkpoints.md) closeout with the completion handoff.

Scripts assist; main owns decisions.

## Authority and commits

All SFD execution is **EXECUTE_WITH_COMMIT**, regardless of section count. Before product/test writes, use an authorized non-main feature branch. Workers never commit or manage branches: they apply changes directly to the working tree — never as a patch file; a result diff is a report — and main is the sole committer and branch operator. State this nowhere else in the skill, packets or dispatch messages; each worker role's developer instruction already binds it. A PLAN_HANDOFF or REVIEW_ONLY request does not authorize implementation, synthetic commits or branch mutation just to satisfy this policy.

Automatic activation announces actual trigger evidence and waits after the first proportional plan, before review. Explicit invocation skips only that routine pause, not missing scope/owner/safety decisions or real subagents. From main, scoped feature branching needs no extra approval. From an unrelated non-main branch, resolve the base choice; do not ask again when continuing the same approved branch. No push, main merge, PR, reset, clean, history rewrite or discarding user work without separate authority. An explicit no-commit execution request is a conflict to resolve before writes, not an alternative SFD mode.

Keep `.agent-work/` locally excluded and untracked. Already tracked workflow files require an index-cleanup decision. Coherent implementation/repair/integration changes are committed; workflow state is not. Completed plans stay closed. Later requests may read the archive but do not inherit its CLEAN or automatically reopen it.

## Evidence and barriers

A PLAN barrier requires both current clean coverages, not approval text, queued jobs, early CLEAN or a timeout. Require the executing host's actual terminal result — the embedded profile names its native evidence form; progress or early text never opens a barrier. Subagent intermediate call products — native partial work and external spawn/wait/close/final raw returns — are never copied or saved as files: record transport, raw ID, requested/observed identity and outcome as one ledger line in FEATURE-STATE, and preserve only the subagent-authored report files written into the dispatch-authorized `.agent-work` folder. A native result labeled “external” is still native. Never record one transport's ID in another transport's field.

Reuse successful unchanged-head/environment evidence. Checks not run stay explicit. Preserve original reviewer reports separately from main's admission; a rejected NIT must not disappear from the ledger. Keep physical attempts (including failed/partial calls) distinct from logical coverage; requested models do not prove observed models.

At completion consolidate final head, checks, closure and evidence pointers in PLAN-FULL, archive immediately and report the efficiency-log closeout ([efficiency checkpoints](references/efficiency-checkpoints.md)) with the completion handoff. Never synthesize missing evidence or report a tool/test as run without its actual result.

## Load detailed procedures only when their boundary applies

[Section planning](references/section-planning.md) owns plan admission and concrete examples; [scope control](references/scope-control.md) prevents new promises. Use [subsections](references/subsections.md) for a real coupled parent decomposition and [long-horizon](references/long-horizon.md) only for an actual multi-session program. Use [parallel execution](references/parallel-execution.md) only for approved overlap, [integration/testing](references/integration-and-testing.md) for composition, and [advisor escalation](references/advisor-escalation.md) for unresolved diagnosis. Artifact cleanup/resume belongs to [lifecycle](references/artifact-lifecycle.md) and [recovery](references/recovery-and-migration.md); efficiency self-checks to [efficiency checkpoints](references/efficiency-checkpoints.md). Do not load every reference for each dispatch.

External protocol — fields, admission, lifecycle and payloads — belongs to the installed `$external-subagent` skill and its live tool descriptions; on any contract doubt, read that skill before improvising. [external-subagent.md](references/external-subagent.md) keeps only this project's client discipline. Suspected no-progress observation follows the plugin's observe contract — never routine polling. A CLI/MCP rejection is a transport/configuration problem until evidence shows otherwise, not proof a stronger model is required.

General-audit owns accumulated investigation, not this change’s acceptance. Its use is optional; no mandatory steward/audit/preflight chain. The efficiency log covers this run only; cross-feature process retrospective belongs to general-audit.
